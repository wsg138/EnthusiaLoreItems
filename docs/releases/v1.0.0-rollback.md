# EnthusiaLoreItems 1.0.0 rollback instructions

These instructions are for reverting a production upgrade from `1.0.0-rc.1` to the previously verified RC after a failed `1.0.0` deployment.

## Before upgrade

1. Stop the server cleanly. Do not copy a live SQLite database as the rollback source.
2. Preserve the entire LoreItems data directory, including `plugins/EnthusiaLoreItems/loreitems.db` and any SQLite sidecar files that are present after shutdown.
3. Record SHA-256 hashes for the backup files and store the backup outside the live plugin directory.
4. Preserve the exact previously deployed `1.0.0-rc.1` jar and verify it against its published release checksum.
5. Record the current schema/startup state and confirm the backup can be read before changing the live installation.

## Roll back

1. Stop the server cleanly.
2. Move the failed 1.0.0 live database/data directory aside. Do not overwrite the only copy of it.
3. Restore the complete pre-upgrade LoreItems data backup to its original path.
4. Restore the exact verified `1.0.0-rc.1` jar.
5. Start the server normally.
6. Verify LoreItems enables without migration/integrity errors, queued work resumes as expected, and staff commands/API access are available.
7. Run the repository-defined Sentinel `restart` verification profile against the restored deployment.
8. Verify database integrity and representative tracked-item/delivery state before reopening normal operation.

## Prohibited shortcut

Do **not** downgrade only the jar while leaving a database that has already been opened or mutated by 1.0.0. The supported rollback boundary is the matched pair of the prior jar and the pre-upgrade database backup.

## Evidence to retain

Keep the pre-upgrade backup hashes, restored database integrity result, RC jar checksum, startup/restart logs, and operator verification result with the release incident record.
