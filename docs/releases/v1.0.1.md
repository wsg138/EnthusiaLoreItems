# EnthusiaLoreItems 1.0.1

EnthusiaLoreItems 1.0.1 is the production-hardening patch release following the immutable `v1.0.0` production release. It contains no schema migration and is intended to publish only after the repository's current deep-review, exact-head CI/static, artifact, and Sentinel gates are satisfied.

## Runtime baseline

- Java 21.
- Paper/Leaf-compatible Minecraft 1.21.11 server baseline.
- SQLite remains the production persistence backend.
- The public `LoreItemsServiceV1` contract remains compatible with the EnthusiaTags integration.
- Geyser/Floodgate server-visible identity behavior remains supported for distribution recipient binding.

## Production-hardening changes

This patch preserves the completed WP-01 through WP-06 history and hardens the shipped plugin implementation and release path. The candidate includes fixes that:

- preserve one-use mass-distribution source-marker uniqueness instead of overwriting an existing marker;
- reject invalid negative SQLite shutdown timeouts before runtime state changes;
- keep a closed SQLite runtime terminal and return a terminal startup result when shutdown supersedes queued startup work;
- treat the successful SQLite commit as the durability boundary even if post-commit autocommit restoration fails;
- reject hot reloads for settings captured by startup-created workers instead of partially applying them;
- preserve editor/destructive-confirmation state across rejected configuration reloads;
- use the normal declared SQLite JDBC dependency path for packaged runtime provenance; and
- derive stable release publication identity from the exact candidate's source-controlled release version rather than targeting the immutable `v1.0.0` release again.

## Upgrade from 1.0.0

1. Stop the server cleanly.
2. Take and verify a backup of the LoreItems data directory before replacing the plugin jar.
3. Replace the `1.0.0` jar only with the verified `EnthusiaLoreItems.jar` asset from the immutable `v1.0.1` release and verify its published SHA-256 checksum.
4. Start the server normally and verify LoreItems startup, SQLite integrity, queued-work recovery, public API registration, tracking, and staff commands.
5. Run the repository-defined Sentinel `restart` verification profile for the exact deployed artifact; only `PAPER_RESTART_OK` satisfies the restart gate.

No database migration is added by this patch. The backup remains required because rollback must restore a known matched pre-upgrade state rather than assume that runtime writes made while 1.0.1 was active are safe to reinterpret after a downgrade.

## Release contents

The GitHub release publishes the exact CI-verified shaded jar together with its SHA-256 checksum, CycloneDX SBOM, Gradle runtime dependency manifest, normalized jar-entry manifest, deterministic production-hardening profile, automated test-report bundle, acceptance/release evidence, and rollback instructions.

## Release gate

Publication remains fail-closed: the stable release workflow consumes only the successful `main` CI artifact for the exact target SHA, validates the source-controlled version and artifact metadata, and requires the committed acceptance evidence to approve the exact source head and JAR hash. The separate deep-review campaign must also have reached its required two consecutive clean independent reviews before the hardening PR is merged.

## Rollback

Follow `v1.0.1-rollback.md`. Do not mutate or retarget the existing `v1.0.0` tag or release.
