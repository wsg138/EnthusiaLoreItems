The release must remain blocked until a legitimate exact-candidate Codacy PASS is obtained and exact-candidate Sentinel restart reaches `PAPER_RESTART_OK` under normal resource gates.

## Independent audit passes

### A — lifecycle and catastrophic failure

Reviewed plugin enable/disable/reload wiring, storage lifecycle, delivery/mutation/reconciliation workers, bounded executors and shutdown behavior. The plugin does not publish a half-ready service as successful. Post-physical-side-effect persistence ambiguity routes to explicit review rather than blind retry. No confirmed item-loss, wrong-player delivery, DB-corruption, runaway-task, startup/shutdown, or unrecoverable restart defect was found.

### B — concurrency and threading

Reviewed Bukkit main-thread guards, DB/filesystem offload, futures/callbacks, claim cycles, queues, shared state and shutdown rejection. Physical Bukkit inventory/entity mutations are main-thread guarded/rebound. SQLite work is serialized through a bounded DB executor. Group-file I/O uses a dedicated blocking executor. Distribution claim work is fenced and queues/debounce registries are bounded. No credible double-processing race, unbounded queue, or off-thread Bukkit mutation was confirmed.

### C — persistence and SQLite

Reviewed migrations V1-V8, transactions/rollback, WAL/FK/busy timeout, claims/leases, deleted markers, revisions, campaign/delivery durability and recovery. `MigrationUpgradeMatrixTest` builds/upgrades every committed schema version with seeded live state, checks `PRAGMA integrity_check`, FK integrity and expected indexes, and proves interrupted migration rollback/retry. Direct-delivery failure-matrix tests use real temp SQLite databases and storage-runtime restarts. No unsafe migration or unrecoverable partial-write state was confirmed.

### D — identity and duplication

Reviewed PDC identity codec, scanners/listeners, delivery reservation, template updates, destructive removal and anomaly paths. Identity requires coherent version/definition/instance/revision, amount/max-stack one and valid types/UUIDs. Template serialization clears LoreItems identity PDC before storing reusable templates. Delivery durably reserves a unique instance before physical insertion; post-insert persistence failure becomes REVIEW_REQUIRED rather than ordinary retry. No sequence was confirmed that yields two legitimate successful copies for one identity or silently turns a valid physical copy into an untracked legitimate instance.

### E — editor/template

Reviewed editor sessions, held-item replacement, codec, permission rechecks, expiry, preview/cancel/confirm, revision persistence and rollout. Sessions are bounded/expiring, chat callbacks rebind to main thread, permissions are rechecked, stale session IDs and duplicate confirms are fenced, and held-item replacement strips hidden LoreItems identity. No release-blocking malformed-template or identity-cloning path was confirmed.

### F — destructive administration

Reviewed exact-instance removal, purge/delete snapshots/confirmation, pause/resume/review, physical preflight, stale references, retries and recovery. Physical identity/fingerprint is checked immediately before destruction; stale/mismatched references refuse destruction; durable preparation precedes physical effect; post-effect persistence failure becomes review. No changed-target destruction path was confirmed.

### G — mass distribution

Reviewed source fingerprinting/one-use handling, recipient normalization, campaign snapshots, binding, claims, cancellation fencing, full inventory/offline defer, restart recovery and reconciliation. Group files are bounded and traversal/symlink checked; duplicate normalized recipients are rejected; physical insert follows durable preparation; cancellation can intercept claimed/prepared work; ambiguous completion routes to review. No repeated-execution/restart path was confirmed that awards a recipient twice as a normal successful outcome.

### H — Geyser/Floodgate and identity

Reviewed literal/already-prefixed `*` Bedrock names, optional Floodgate lookup, cached name/UUID binding and unresolved identities. Floodgate players are prefixed when needed, already-prefixed names are not double-prefixed, non-Floodgate resolution for a `*` recipient is refused, and unavailable Floodgate integration leaves Bedrock names unresolved rather than guessed. No wrong-player binding path was confirmed. Real Microsoft/Xbox authentication remains outside the approved scope.

### I — protection/event integration

Reviewed protection listener/tracking coverage for despawn/combust/merge/damage/void, durability/consumption, result slots, shulker/bundle restrictions, crafting/crafter/cooking/fuel/brewing/compost, placement/hanging/entities, flowerpots/buckets, consumptive interactions, projectile/elytra/ammo/bow, dispense and related movement paths. Malformed identity evidence is treated protectively/fail-closed. No credible release-blocking bypass was confirmed.

### J — public API and EnthusiaTags

Reviewed LoreItems v1 API/registration and the actual current Tags consumer. Tags uses Bukkit ServicesManager with no LoreItems implementation, DB, or command coupling. Missing/unavailable service, exceptions, null stage and timeout become retry; stable claim-derived external operation IDs are persisted before invocation; operation-ID mismatch/permanent validation become review. Tags has a contract test that hashes the production LoreItems JAR and an end-to-end crash/replay idempotency test proving one physical award. No credible duplicate-reward/API-coupling defect was confirmed.

Deploy only release asset `v1.0.0` with SHA-256 `7c862b0ae545d710a33267ad6e19a4ae26d97323e97f40707c1475c9f9ba7063`; do not deploy an ad-hoc rebuild or current documentation-only `main` artifact.

5. Watch for migration/SQLite integrity/FK errors, degraded-read-only activation, executor rejection/queue saturation, duplicate/anomaly warnings, and unexplained REVIEW_REQUIRED bursts.
