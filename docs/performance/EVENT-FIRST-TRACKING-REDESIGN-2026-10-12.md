# Event-first LoreItems physical tracking: one-minute fallback and precise cursor/slot ownership

Status: **design and partial implementation only**. No production rollout. Read together with [issue #39](https://github.com/wsg138/EnthusiaLoreItems/issues/39), [#45](https://github.com/wsg138/EnthusiaLoreItems/issues/45), [#71](https://github.com/wsg138/EnthusiaLoreItems/issues/71), and open performance PRs #79 / #80.

## Owner's operational intent

1. **Never intentionally load an unloaded chunk to find lore items.** Ordinary movement cannot occur in unloaded block inventories under normal ticking. Keep the last confirmed location and reconcile if/when a chunk loads naturally. Never silently erase durable evidence merely because a chunk is inaccessible. World edits, admin commands, alternate plugins, and external data mutation are exceptional reasons to revalidate on natural load.
2. **Event-first:** when a tracked identity or potential/partial lore metadata moves by player click, drag, shift-click, number-key swap, double-click, drop, pickup, hopper, block break/place, death, entity transfer, dispenser, etc., determine its actual new state from the post-event server-thread snapshot. No unsound assumptions from pre-event `InventoryClickEvent` slot/cursor values; the event can be cancelled/modified. Preserve exact `player inventory slot / armor slot / offhand / ender slot / cursor / container slot / nested path / display / dropped item` evidence.
3. **Fallback at most once per 1,200 server ticks (~60s at 20 TPS) for an eligible loaded location**; do not blindly sweep all loaded chunks or all player inventories every tick. Poll a bounded set of *known tracked* loaded locations and dirty/unknown locations fairly. Per-location cooldown and per-tick wall-time budget, not 16 potentially expensive unrestricted inventories per tick. A cooldown delays routine verification only—not authentic movement/lifecycle events.
4. **Natural-load discovery:** capture real chunk-load and plugin-start loaded-chunk epochs only when needed; read tile entities without full snapshot (PR #79), build a bounded known-tracked location index and mark proof of completed scan. Loaded chunk observation **must never become a silent permanently rejected request**; if admission is full, retain bounded dirty/retry evidence or a durable catch-up cursor/generation that revisits accessible loaded chunks. If a chunk unloads first, its tracking remains LAST_CONFIRMED; no forced reload.
5. **Untracked fast path:** do not snapshot both inventories and schedule two full scans on every normal untracked hopper move. A cheap metadata/evidence check is safe as long as nested shulker/bundle identities and partial/malformed identity markers remain observable; the latter must fail closed through reconciliation and anomaly detection.
6. **Single-authority identity semantics:** never declare UNIQUE / PRESENT unless the bounded post-event scan covers the relevant accessible scope; if observations are truncated, ambiguous, cancelled, invalid or cross-container, emit only reconciliation/REVIEW_REQUIRED, preserve evidence, and revisit safely. Copy/dupe detection must retain both copies rather than collapsing on instance ID. Do not suppress separate protection/anomaly/template events unless shown to be redundant by tests.

## Audit of the current code (2026-10-12 `main`)

- `PaperPhysicalTrackingListener.start`: starts `drain()` **every tick** and `seedLoadedChunks()` every **100 ticks (~5s)**. Seed requests are bounded by `mutation-budget-per-tick` (default 16) per seed call; queue capacity is 32 × budget (=512 default).
- `onChunkLoad` enqueues **every** chunk-load event as a distinct non-periodic request, without by-coordinate/epoch dedup. Admission failure increments an event reject and drops the incoming request. A rejected chunk may later be found by the routine sweep, but that is not a proven recovery guarantee.
- `onChunkUnload` synchronously scans chunk entities and all block containers as LAST_CONFIRMED. This is distinct from routine loaded-chunk discovery and can block the main server thread. Never simply remove this boundary without proving last-location integrity; use an already built loaded-location index and bounded identity-preserving unload handling when implementing replacement.
- `PaperUniqueAccessTrackingListener` already handles click, drag, close, cursor, offhand, armor, main inventory, ender chest and open top container. It currently rescans the entire player + container after many ordinary clicks; a future targeted mutation observer may use event action/slots as a *hint* but should read canonical actual post-event state to prevent false authority, and fall back to bounded wider scan when ambiguous (shift clicks, hotbar swaps, double-click, creative/other plugin mutations, nested containers).
- `PaperPlayerScanCoalescer` coalesces only `(playerId, source)` until next tick; different event-source strings can rescan the same player separately.
- `PaperHopperMoveObservation` on main snapshots **both** source and destination for **all** `InventoryMoveItemEvent` and schedules next-tick source/destination inventory scans. That hot path is independent of the rejected deferred chunk scan queue. This PR adds a cheap no-identity-evidence fast path while still retaining the full path for tracked, nested and malformed identity metadata.
- `PaperTemplateUpdateEvents` and `PaperIdentityAnomalyListener` separately process the same hopper and GUI events. A single listener optimization does **not** remove their work; coordinate measured changes and privacy/tracking invariants before consolidating them.
- A currently empty queue with a historical peak of 512 **does not** prove the overloaded requests were successfully observed later. Live 2026-10-12 ~17:31 and subsequent diagnostics displayed cumulative event rejections **18,600 → 20,357**, periodic rejections **61 → 73**, coalesced player scans **43,177 → 45,811**; the timestamps must be aligned to compute a true rate. A healthy instant TPS did not prevent 17:10–17:14 AI-OFF lag to 12.61 TPS, [Spark](https://spark.lucko.me/bqdk6suGQu). Those rejection counters are for queued player/chunk event scans, **not ordinary hopper moves**.

## Required architecture work — do not shortcut

### A. Loaded chunk generation and dirty admission ledger

Use `(world UUID, chunkX, chunkZ, load generation)` in a bounded coalescing admission ledger. Multiple load events for the same currently loaded generation cause one relevant admission, but unload invalidates that epoch; unload→reload must be independently discovered. Use a `DIRTY_NEEDS_RESCAN` marker when requests are coalesced or capacity is exceeded; reconcile without force-load, remove only after a successful complete scan, and never confuse temporary inaccessible/skipped scan with success. Capacity overflow of this marker itself needs a bounded global catch-up sweep state with a stable cursor, not unbounded key accumulation.

Build tests for 1,000 repeated same-chunk loads, 1,000 distinct chunks over capacity, alternating load/unload and hot reload, multiple worlds sharing X/Z, chunk unloading before retry and real user movement during the dirty window. Important: no duplicate `PRESENT` authority and no loss of missed-evidence recovery.

### B. Event-first move index

For each item identity, store ephemeral *accessible* location descriptors and the latest committed durable evidence/revision, indexed by container location and player UUID; do not retain strong Bukkit `Chunk`, `World`, `Inventory`, `ItemStack` or `Player` references across ticks. On an actual item movement, read the moved stack's evidence, then schedule one bounded post-event follow-up for only affected inventories/slots/cursor plus exact peers. Maintain last-confirmed when inaccessible and reconcile on next natural access. Index must not trust a single identity location when duplicates exist.

Tests include cursor→slot, slot→cursor, two-slot swap, quick move/shift click, double-click, number-key hotbar swap, offhand, drag across multiple slots, ender/chest double container, item frame, hopper, nested shulker and bundle, plugin-cancelled event, inventory close and reconnect, duplicate same identity and malformed PDC. Test both ordering and persistence barriers (no false delete or accepted-before-committed claims).

### C. Periodic reconciliation

No scanning every five seconds merely because a chunk is loaded. Default per-location routine cooldown **at least 60 seconds**, with jitter/stagger and configurable bounded work per tick for **known-tracked or dirty accessible** locations. On startup, formerly loaded chunks without a trusted index require a bounded discovery sweep, which can take more than a minute under large workloads; make this explicit instead of claiming every unknown container is verified within 60s. No force-load. Allow immediate scans for real lifecycle events that may carry important evidence despite cooldown.

Measure *attempted / coalesced / executed / skipped / failed / retried / permanently unresolved* counts per source, queue age p95/max, dirty generation backlog, full per-tick wall-time and maximum one-pass scan time. A zero-count exception is not evidence of zero lag. Keep fixed-cardinality metric labels and bounded logs.

## Acceptance and deployment boundaries

- Requires PR #79 integration (non-snapshot block holders and `chunk.getTileEntities(false)`) and PR #80's truthful success/failure/skipped counters and peak timing **or compatible independently-reviewed equivalents**. These two drafts are NOT a fix for rejection admission.
- Stress CI + disposable Paper 26.2 / Java 25 tests must prove all movement paths and queue saturation eventually reconcile without loss/force-loading, while worst callback/tick timing remains bounded. Record real before/after operation timings and MSPT under matched entity/chunk workload.
- No live SMP/SFTP/database edits, restart, AI inference, config toggles, plugin disable/hot reload, or release merge without owner-approved staging, WAL-consistent backup/rollback and exact loaded JAR hash verification.
- Avoid claiming percent improvement from synthetic invocation counts alone. Release gate: zero **unreconciled** accepted or rejected important chunk/player observations in stress scenarios, not merely zero queue-depth at observation time.

Owner intent in plain terms: **detect important item movement immediately; otherwise leave unchanged chunks and containers alone, using a quiet 60-second-or-slower safety sweep only for things likely to contain tracked items.**
