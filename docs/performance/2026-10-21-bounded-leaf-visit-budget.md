# Non-air inventory visit cap — development-only, 2026-10-21

The combined LoreItems AI-OFF candidate (#165) has a 256-unit `PaperScanLimit` and a 2ms **post-operation** drain timeout. Source review identified that ordinary leaf stacks did not spend budget units before identity/PDC reads; only nested-container expansions and chunk container admission did. Thus a dense nested inventory could still perform many more than 256 identity checks within one synchronous callback.

This development-only change spends one shared work unit **before every non-air item-stack visit** in both `PaperTrackedItemCollector.collectItem` and `PaperPhysicalInventoryScanner.scanItem`, in addition to existing per-nested-container expansion charges. Refused visits mark `PaperScanLimit` incomplete and perform no identity/PDC decode. Empty/air stacks do not spend item-visit units. A complete traversal of exactly 256 non-air leaves without nested expansions still remains complete. The 257th never counts as a proof of absence or an authoritative match. Synthetic MockBukkit regressions use a sentinel stack whose metadata methods throw if called after exhaustion.

**Still not a safe production release.** This is a resource cap, not the required generation-fenced continuation cursor: after 256 visits, evidence beyond the limit is unknown. The existing recursive *pre-probe* `nestedEvidenceWithIdentityEvidence` and `hasIdentityEvidence` traversals may do extra work not metered by the same limit; separately enforce their costs before claiming a strict 256-operation bound. Already-issued authoritative observation callbacks are not automatically revoked when a later visit truncates; safely buffer or downgrade full-scope evidence before any durable confirmation. Do not force-load chunks or retain Bukkit objects across ticks. Tests must cover mid-cursor mutations, all 54 double-chest slots, database ACK, prior plugin-outage gaps and AI-OFF MSPT.

This PR must pass its **own exact-head** CI/Codacy, Java/Paper tests, review and matched performance assessment before any development integration. No `main` merge, live SMP/TEST JAR, server restart, SFTP or player/SQLite mutation authorized.
